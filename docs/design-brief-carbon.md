# 디자인 브리프 v2 — Carbon에게 (2026-11-18)

> 이 문서 하나로 작업할 수 있게 썼다. 모르는 게 있으면 지어내지 말고 맨 아래 "돌려줄 질문"에 적어 달라.

## 1. 서비스 한 줄
**sudo-patch** — 서버 패치·EOL 점검 플래너. `pip freeze`로 만든 requirements.txt와 OS·Python 버전을 받으면,
Agent가 지원 종료일(endoflife.date)·취약점(OSV)·최신 버전(PyPI)을 조회해 **회차별 패치 계획**을 만든다.
설치할 수 없는 버전이 나오면 Python 업그레이드로 다시 계획(재계획)하고, 확정하면 캘린더에 등록한다.

사용자: 서버를 관리하는 개발자·운영자. 화면은 데이터가 많다(패키지 수십 개, 버전 숫자, 로그).

## 2. 이번에 바꾸려는 것
지금 기준(`docs/design.md`)은 차분한 단색 "보안 관제(SOC) 대시보드"다. **화면 구성(아래 5절)은 유지**하고, 느낌을 아래처럼 바꾼다.

| 키워드 | 뜻 |
|---|---|
| **버전 패치** | 로고는 릴리즈 버전 세 자리 `MAJOR.MINOR.PATCH`(예: 1.1.1)를 담는다 |
| **붙이는 패치** | 옷·가방에 붙이는 **와펜(자수 패치)·스티커**를 화면 요소로 쓴다. 점선 박음질 테두리가 기본 표지 |
| **3D + 팝** | 패치를 수행하는 요소(패키지 카드 등)가 **상자나 Mac 폴더 같은 용기 안에 있다가 튀어나온다** |
| **네온 + 움직임** | 어두운 바탕 위 네온 색. 정지한 화면보다 살아 움직이는 화면 |
| **수집** | 패치를 모으는 요소(9절). 지금은 디자인만, 기능은 나중 |

이전에 만든 sudo-quest는 아이소메트릭 게임 느낌이었다. **이번에는 아이소메트릭을 쓰지 않는다.**

## 3. 로고 — 방향은 정해짐
- **바탕:** 방패 모양 와펜 + 안쪽 점선 박음질.
- **안쪽:** 버전 세 자리를 나타낸다. 후보는 셋이고 **A 추천**.
  - **A. 계급장 세 줄**(셰브론 3개): 위에서부터 PATCH(네온 그린, 켜짐) · MINOR · MAJOR(흐리게). "한 단계씩 올린다"
  - **B. 버전 점 세 개**(`●.●.●`): 마지막 점이 켜지고 위로 화살표
  - **C. 링 세 칸**: 원형 와펜, 고리를 세 칸으로 나눔
- **워드마크:** `sudo-patch`, JetBrains Mono.
- **필요한 크기:** 파비콘 16·32px, 사이드바 로고(가로 240 안), README 배너, 큰 표지. **16px에서 셰브론이 뭉개지지 않는지** 꼭 확인할 것. 뭉개지면 작은 크기용 단순한 안을 따로 만든다.

## 4. 원하는 결과물
| # | 결과물 | 형식 |
|---|---|---|
| 1 | 로고 최종 2~3안 + 작은 크기용 변형 | SVG |
| 2 | 네온 색 토큰 (바탕·면·선·글자·강조·위험도 5단계·재계획·수집 등급 3단계) | 표 (토큰 이름, 값, 쓰임) |
| 3 | 패치 카드 컴포넌트: 기본·위험도별·팝 직전/직후·붙은 상태 | SVG 또는 HTML/CSS 시안 |
| 4 | 3D 장면 콘셉트: 용기(상자/폴더) 모양, 열리는 방식, 팝 궤적, 카메라 | 스케치 + 설명 |

| 6 | 화면 5개 시안 (5절) | 이미지 또는 HTML 정적 시안 |

데스크톱 1440×960 기준. 모바일은 화면 01만 대략 어떻게 접히는지 보여주면 충분하다.

## 5. 화면 구성 (유지)
공통: 왼쪽 사이드바 240px(로고, 메뉴, 대상 서버 카드) + 상단바(제목, 세션, 새 대화).

1. **대화 + 실시간 실행 단계**: 핵심 숫자 4개(CRITICAL 패키지, HIGH 이상, 재계획 횟수, 응답 시간) / 파일 올리기 / 대화 / 오른쪽에 실행 단계가 실시간으로 쌓임
2. **회차 계획 보드**: Python 업그레이드 경로(예: 3.8 → 3.9 실패 → 3.10 지원 종료 → 3.11 확정) / 회차별 칸(최대 3회차) / 실행 순서 / 안전·확인 못 함·보류·조회 제외 목록
3. **캘린더 + 계획 관리**: 월 달력(패치 회차, 내 일정, 겹쳐서 옮긴 회차는 "원래 날짜" 표시) / 저장한 계획 수정·삭제·겹침 경고 / 내 일정 추가
4. **실행 로그**: 세션 목록 / 이벤트 시간순(#번호) / 판단 근거(왜 이 버전, 왜 이 순서)
5. **(새) 패치 도감**: 9절

## 6. 움직임을 거는 순간 (실제 이벤트)
화면은 서버가 실시간으로 보내는 이벤트를 받아 그린다. 이름은 `app/agent/graph.py`에 있는 그대로다.

| 이벤트 | 뜻 | 움직임 아이디어 |
|---|---|---|
| `step_start` / `step_end` | 단계 시작·끝 (분석 → 조회 → 판단 → 계획 → 응답) | 용기가 열리기 시작 / 닫힘 |
| `tool_call` / `tool_result` | 외부 조회 1건 (지원 종료일·취약점·버전) | 패키지 카드가 하나씩 튀어나옴, 결과 등급 색으로 점등 |
| `judgment` | 패키지마다 판정 | 카드에 등급 패치가 붙음 |
| `replan` | 설치 못 하는 버전 → Python 업그레이드로 다시 계획 | 카드가 흔들리고 용기로 돌아갔다 다시 나옴 (경고색) |
| `calendar_check` | 캘린더와 겹쳐 회차 날짜를 옮김 | 회차 카드가 옆 날짜로 미끄러짐 |
| `plan_built` | 회차 계획 완성 | 카드가 회차 보드에 "착" 붙음, 박음질이 그려짐 |
| `error` | 조회 실패 등 | 짧고 분명하게. 과한 연출 금지 |
| (확정) | 사용자가 계획 확정 | 박음질 완성 + 수집 패치 획득 연출 후보 |

## 7. 꼭 지킬 것
- **읽어야 하는 곳은 평평하게.** 표, 버전 숫자, 로그, 날짜는 3D·기울기·흐림 없이 또렷하게. 3D와 큰 움직임은 헤더, 빈 화면, 전환 순간, 위 이벤트 순간에만 쓴다.
- **동작 줄이기**(`prefers-reduced-motion`)를 켜면 정지 화면으로 대체한다. 3D를 못 그리는 환경의 대체 화면도 같이 설계한다.
- **색만으로 구분하지 않는다.** 위험도는 항상 글자(CRITICAL 등)와 같이. 네온 색 위 글자는 대비 4.5:1 이상.
- **위험도 색과 수집 등급 색이 겹치지 않게.** 예: CRITICAL(빨강 계열)과 MAJOR 수집 등급(핫핑크)은 한눈에 구분돼야 한다. 둘을 어떻게 나눌지 제안해 달라.
- **확인 못 한 값은 "미상" / "확인 못 함"으로 보인다.** 이 상태도 디자인에 포함 (회색, 점선 등).
- **성능:** 3D 장면은 화면에 하나. 패키지 수십 개를 모두 3D로 그리지 않는다.
- **글꼴:** 본문 IBM Plex Sans KR, 숫자·버전·로그 JetBrains Mono (바꾸자는 제안은 환영).

## 8. 구현 쪽 사정 (참고)
- 화면은 이후 **Vite + Vue**로 만든다(Claude Code 담당). 3D는 Three.js 계열을 생각 중. 다른 걸 추천하면 이유를 적어 달라. **설치는 하지 않는다.**
- 디자인 토큰은 CSS 변수 이름으로 바로 옮길 수 있게 `--color-…`, `--space-…` 형식으로 지어 달라.

## 9. 수집 패치 (디자인만, 기능은 나중)
버전 세 자리를 **희귀도**로 쓴다.

| 등급 | 희귀도 | 획득 예시 (확정 아님) |
|---|---|---|
| PATCH | 흔함 | 첫 CVE 해결, 계획 첫 확정 |
| MINOR | 드묾 | Python 업그레이드 확정, 재계획을 거쳐 성공 |
| MAJOR | 전설 | OS 지원 종료 탈출, CRITICAL 0개 달성 |

- 디자인할 것: 등급별 패치 모양·테두리·광택 차이, 획득 순간 연출, 도감(재킷·가방에 붙여 모으는 판 같은 느낌), 아직 못 얻은 패치(실루엣).
- 획득 조건은 나중에 명세에 넣고 **코드가 계산한다**(LLM이 정하지 않음). 조건 아이디어는 제안만 해 달라.

## 10. 작업 방식
- **브랜치:** `agy/design-v2`에서만 작업한다. main에 직접 커밋하지 않는다 (Claude Code가 확인 후 합침).
- **결과물 위치:** `docs/design-v2/` 아래에만 둔다 (`README.md` + svg/html/이미지). `app/`, `tests/`, `web/`, `requirements.txt`는 건드리지 않는다.
- `docs/course/`는 읽지도 인용하지도 않는다.
- 끝나면 `docs/HANDOFF.md`의 "지금 하던 것"에 한 줄 남긴다.
