# agy 사용 가이드 (sudo-patch, 3일 프로젝트)

## 기본 원칙
- **구현은 Claude Code.** agy는 조사·리뷰·막힌 문제·한도 찼을 때 이어받기만 한다.
- **방법 A로만 쓴다.** 같은 폴더에서 터미널을 하나 더 열고 `agy` 실행 → 아래 문장을 붙여넣기. (플러그인 방법 B는 3일 동안은 쓰지 않음)
- agy는 AGENTS.md를 읽는다. GEMINI.md는 만들지 않는다.
- agy가 코드를 바꿀 땐 `agy/` 브랜치에서만. `--yolo` 금지.
- 리뷰 결과는 "무조건 반영"하지 않는다. Claude Code에 넘겨서 판단하게 한다.

## 언제, 어떤 모델로
| 시점 | 할 일 | 모델 | 왜 agy인가 |
|---|---|---|---|
| ① 0~1일차 오전 | API 이용 조건 조사 | Flash | 가벼운 웹 조사. Claude 사용량 아끼기 |
| ② 2일차 끝 | 교차 리뷰 | Carbon | 다른 모델이 봐야 Claude가 놓친 걸 잡음 |
| ③ 3일차 제출 전 | 코드 전체 vs spec 대조 | Carbon | 긴 컨텍스트에 강함. 느리니 수동 테스트하는 동안 돌려두기 |
| ④ 언제든 | Claude가 같은 문제를 두 번 실패 | Carbon | 다른 관점의 두 번째 엔지니어 |
| ⑤ 언제든 | Claude 5시간 한도 참 | Carbon | 인수인계 후 이어서 구현 |

## 붙여넣을 문장

### ① 이용 조건 조사 (Flash)
```
endoflife.date API, OSV.dev API, PyPI JSON API 각각의
이용 조건(호출 한도, 약관, 출처 표기 요구, User-Agent 요구)을 공식 문서에서 찾아줘.
docs/research/api-terms.md에 API별로 3~5줄씩, 출처 URL과 확인 날짜를 붙여서 써줘.
공식 문서에 없는 내용은 "명시 없음"이라고 쓰고 추측하지 마.
코드는 건드리지 마.
```

### ② 교차 리뷰 (Carbon)
```
docs/spec.md의 "판단 규칙"과 "완료 기준"을 기준으로
main 브랜치의 app/ 코드를 리뷰해줘. 코드는 고치지 마.

특히 볼 것:
1. 목표 버전 고르기가 spec 규칙대로인지 (호환되는 최신 → 취약점 0건 확인)
2. 재계획 상한 3회가 실제로 지켜지는지
3. LLM이 계산(버전 비교·정렬·회차 나누기)을 하는 곳이 있는지
4. API로 확인 못 한 값을 지어내는 곳이 있는지
5. Tool이 예외를 밖으로 던지는 곳이 있는지

결과는 docs/review-day2.md에 "심각도 / 파일:줄 / 문제 / 근거" 표로 써줘.
확실하지 않은 건 "확인 필요"로 표시해줘.
```
→ 끝나면 Claude Code에: `docs/review-day2.md를 읽고, 맞는 지적만 골라서 고칠 계획을 보여줘. 틀린 지적은 이유를 적어줘.`

### ③ 제출 전 대조 (Carbon)
```
docs/spec.md의 "완료 기준" 항목마다
이 저장소의 어느 코드와 어느 테스트가 그것을 보장하는지 찾아줘.
보장하는 테스트가 없는 항목은 "테스트 없음"으로 표시해줘.
코드는 고치지 말고 docs/review-final.md에 표로 써줘.
```

### ④ Claude가 두 번 실패한 문제 (Carbon)
먼저 Claude Code에: `지금 막힌 문제를 docs/HANDOFF.md "주의"에 정리해줘. 시도한 방법 2개와 각각 왜 실패했는지, 재현 명령어를 포함해서.`
그다음 agy에:
```
docs/HANDOFF.md와 git log -5를 읽어줘. "주의"에 적힌 문제를 풀어야 해.
agy/fix-<짧은이름> 브랜치를 만들어서 작업하고,
pytest -q가 통과하면 커밋해줘. 앞서 실패한 두 방법은 다시 쓰지 마.
```
→ 끝나면 Claude Code에: `agy/fix-<이름> 브랜치의 diff를 리뷰하고, 괜찮으면 main에 합쳐줘.`

### ⑤ 한도 찼을 때 이어받기 (Carbon)
Claude Code에(한도 차기 직전): `인수인계해줘`
agy에:
```
docs/HANDOFF.md와 git log -5를 읽고 이어서 진행해줘.
agy/continue 브랜치에서 작업하고, 작업 단위마다 커밋 + HANDOFF.md 갱신해줘.
```
→ Claude 한도가 돌아오면: `agy/continue 브랜치를 리뷰하고 main에 합쳐줘. 그다음 이어서 진행해줘.`

## 쓰지 않는 것
- 매 작업마다 자동 리뷰 (사용량 폭증)
- agy에게 처음부터 기능 구현 맡기기 (구현자가 둘이면 코드 스타일·판단이 갈라짐)
